Role-aware model, effort and capacity routing

The governor never knows an exact number of Turns left. It combines OpenAI's broad Pro 20x planning ranges, live window telemetry when available, and local per-workload measurements. Its objective changes by role, phase, difficulty and fault impact.

What changed after review. Removed “capacity known” and “model state.” Effective snapshot identity is audit evidence, not an automatic work blocker. Replaced one permanent cell per role with workload menus. The easy one-run fixtures below cannot reject high reasoning for hard Challenges or the need for several high-effort Turns.

What the four roles actually mean

Triage JudgeOne adaptive batched judge for newly seen ambiguous Challenges. At Run start it protects startup latency; later it runs only for a new ambiguous release batch. Stated difficulty or qualified crowd evidence can eliminate the call.
Solve LeadThe generalist assigned one bounded solving Turn. The Run controller—not this Agent—owns the durable Attempt and may schedule another Turn.
SpecialistA profile-specific solving Turn: web, pwn, crypto, rev, forensics, stego, OSINT, AI or misc. A hard Challenge may need several high-effort Specialist Turns, with Checkpoints between them.
Recovery AgentA fresh bounded invocation for a novel operational fault. It is not a failed-solve fallback. Whole-Run faults value wall time; an isolated noncritical Lane fault may value capacity more.

Capacity governor

Always uncertain. Start with the published lower endpoint, reduce it by the live used percentage when available, subtract a measured Recovery-and-tail reserve, then update from observed Turn costs by role, difficulty, effort and context size.

If telemetry is absent, use the lower official endpoint plus tighter concurrency and Turn bounds. An explicit platform exhaustion response enters Quota wait. Neither case invents another model-specific pool.

API-equivalent price helps rank relative burn; it never converts the subscription into an exact dollar or message balance.

Effort and multi-Turn rule

Difficulty sets the initial comparison band; trusted evidence and verified progress govern continuation. A trivial fixture can compare overhead, but cannot disqualify high/max/ultra for a hard Challenge.

A Checkpoint may justify another Turn at the same or higher effort. Repetition without new verified progress weakens continuation. Model-authored confidence alone never escalates.

Once a Turn begins, requested model and effort freeze. The next boundary may adapt using the durable Attempt record.
