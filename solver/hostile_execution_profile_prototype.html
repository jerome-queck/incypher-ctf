Which hostile-execution profile works?

This demo tests the decision model around one question: when the pinned runtime can enforce every Attempt-executor boundary, which profile may proceed; when it cannot, must a claimed v2 Run refuse, or may an explicitly selected honest partial candidate run with hostile execution disabled?

The observations below came from the exact current arm64 Solver image on Colima 0.10.3. They establish prototype feasibility, not release qualification. Click profiles and failure cases to see the resulting policy.

Unresolved before production.
  • The prototype uses a controller-only set-id unshare binary as a stand-in. Production needs a fixed-policy launcher with no caller-selected namespace, mount, identity, or command arguments.
  • The inner seccomp deny-list proves filter placement; it is not yet the tool-compatible release policy.
  • The outer contract disables Docker’s seccomp and AppArmor profiles. The fixed launcher, trusted-service capability drop, all tool profiles, both architectures, reboot, and hostile Target probes still require the full rig.
  • The official competition runtime has not promised these flags. Rootless Bubblewrap failed, and the ordinary container exposed read-only cgroup v2.
