# v2 closed-ticket delivery audit

Date: 2026-09-13  
Scope: every closed native child of [spec #256](https://github.com/jerome-queck/incypher-ctf/issues/256), current `main` after PR #363  
Method: light source-to-diff audit using issue edit history, merged PR metadata/checks, current production code, tests, proof locks, committed receipts, and the private sibling Rig. No acceptance workload was rerun.

## Verdict

Spec #256 has 67 native children: **37 closed, 30 open**. The closed set is #257–#292 plus #298. All 148 closed-ticket boxes are currently checked and every closed ticket has a merged closing PR. All 38 closing PRs had green hosted checks. This is strong implementation evidence, but it is not a v2 release verdict: the 30 open children include submission, Recovery, most Tool profiles, candidate assembly, policy selection, and the 5.5-hour Gate.

Current classification:

- **31 pass:** current code, tests, and/or retained proof artifacts align with the checked criteria; no contradiction found in a light review.
- **1 concern, repaired:** #268 was incorrectly checked and closed once; PR #363 now supplies the omitted cutover.
- **5 not-lightly-verifiable:** #269, #270, #281, #283, and #298 have implementation and green test/build evidence, but their decisive exact-host, exact-image, external-evaluator, live-native, or built-image qualification receipts were not retained as directly inspectable artifacts in this tree. This is an evidence-retention limitation, not a found implementation failure.

One systemic caution: every ticket's four boxes were manually checked **before merge**; 30 were checked before their closing PR even opened. None was checked from post-merge evidence. All 38 closing PRs have zero hosted reviews and zero PR comments; claims such as “independent review: PASS” survive only in author-written PR bodies. Therefore checkbox state alone is not reliable completion evidence.

## Why #268 was checked before the purge existed

[Issue #268](https://github.com/jerome-queck/incypher-ctf/issues/268) changed from 0/4 to 4/4 at `2026-09-11T07:30:24Z`, 20 seconds before [PR #331](https://github.com/jerome-queck/incypher-ctf/pull/331) opened. PR #331 implemented capability custody, peer checks, executor probes, and atomic setup behavior; green tests exercised those mechanisms. It did **not** complete the broader source decision in [ADR-0040](../adr/0040-one-owner-one-subscription-and-one-observed-limit-state.md): remove the live `.env.incypher`, obsolete Claude/Anthropic/OpenAI API-key and metered-Codex configuration, and stop treating those as active runtime paths. The PR nevertheless repeated “4 of 4,” used `Closes #268`, and merged with no hosted review. CI could not catch an assertion it did not contain.

The owner reopened #268 with the exact omission recorded in [the issue comment](https://github.com/jerome-queck/incypher-ctf/issues/268#issuecomment-5650850217). [PR #363](https://github.com/jerome-queck/incypher-ctf/pull/363) then migrated the machine to `.env`, removed the obsolete live configuration, made setup purge old variables, and made Boot refuse them. Current enforcement is visible in [`scripts/setup-board.sh`](../../scripts/setup-board.sh), [`solver/boot.py`](../../solver/boot.py), [`solver/credentials.py`](../../solver/credentials.py), and [`tests/test_setup_board_cutover.py`](../../tests/test_setup_board_cutover.py).

“Remove Claude” never meant removing contributor compatibility. ADR-0040 explicitly retains `CLAUDE.md`, `.claude/skills/`, and attribution/history. The purge boundary is scored-runtime credentials, inference routes, and active operator configuration.

## Practical conclusion

The closed tickets are not merely empty checkbox claims: each has a merged implementation and targeted tests, and 31 are directly supported at light-audit depth. No second functional omission like #268 was found. But the close process was weak: pre-review checkboxing plus self-authored PR assertions made #268 possible, and five environment-dependent qualification claims need fresh execution or retained exact receipts before relying on them as release evidence. The final candidate manifest and Gate tickets must treat these ticket closures as implementation inputs, not inherited proof.
